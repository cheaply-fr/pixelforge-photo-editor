# Pixel professional toolbar roadmap

This matrix distills the two user-provided toolbar references into an implementation and test plan for Pixel. The references are visual inspiration and capability requirements; Pixel uses its own interaction design, names and icons where that improves browser accessibility.

The menu references and their complete categorized inventory are maintained in [`docs/menu-roadmap.md`](./menu-roadmap.md).

**Neural Filters increment:** Filter → Neural Filters… is an enabled deterministic offline local approximation with editable luminance recovery, colour balance, texture detail and neighbourhood radius. It uses no model, upload or network call; semantic, portrait and generative model parity remains staged. See [`neural-filters-effect-contract.md`](./neural-filters-effect-contract.md). **Filter → Other → High Pass… is also active as a bounded neutral-grey local residual with editable amount/radius, source-safe alpha/padding and desktop/mobile persistence; see [`high-pass-effect-contract.md`](./high-pass-effect-contract.md).** The evidence-based high-use workflow ranking and applied-status audit are maintained in [`top-ten-tools-roadmap.md`](./top-ten-tools-roadmap.md). That document records Edit, Image, Layer, Type, Select, Filter, View and Plugins workflows, including the Image Size dialog and the Filter submenu families.

## Current Pixel baseline

The Edit menu's **Reflection Removal…** action is active as a deterministic,
source-safe local de-glare approximation. It has threshold and cleanup-radius
controls, editable filter metadata, and desktop/mobile persistence coverage;
see [`reflection-removal-effect-contract.md`](./reflection-removal-effect-contract.md).

Pattern Stamp is part of the active Phase 3 retouch increment. Its bounded
local tile model, persisted settings and acceptance gates are defined in
[`pattern-stamp-contract.md`](./pattern-stamp-contract.md).

staged; this increment covers the explicitly named Pattern Stamp tool.

Implemented in this branch (production deployment follows the protected merge): Move, Crop, Brush, Pencil, Color Replacement, Eraser, Text, Rectangle, Ellipse, single-row and single-column marquee presets, layer properties, nondestructive per-layer brightness/contrast/saturation/hue/blur/input-output Levels adjustments, rotate/flip, local/cloud project persistence, optional Cheaply session and production CI/CD. The supplied Cheaply artwork is used in the brand lockup beside an original cyan Pixel monogram.

The active implementation increment adds Hand, Zoom, Eyedropper, Paint Bucket, Gradient, Clone, Healing, Background Eraser, Magic Eraser, Dodge, Burn, Sponge, Smudge, rectangular/elliptical/single-row/single-column/lasso/polygonal-lasso/Magnetic Lasso, pressure-aware Selection Brush and Magic Wand color selection, selection composition (replace/add/subtract/intersect), inversion, feather control and alpha-correct nondestructive masks. **Remove Background** adds a deterministic local edge-connected colour segmentation mask with persisted tolerance, source preservation and explicit limitations; it is not semantic subject detection. Brush, Eraser, Background Eraser, Clone, Healing, Dodge, Burn, Sponge and Smudge use tested bounded radial or sampled-colour primitives; pressure mapping is opt-in and backward-compatible with older drafts, clipped clone destinations preserve the corresponding source range, and queued pointer pressure survives asynchronous decode. Background and Magic Eraser use immutable source samples, tolerance-validated connected regions, transparent-edge normalization and one history commit per gesture. Dodge and Burn use deterministic luminance range masks; Sponge uses HSL vibrance while preserving alpha and transparent-edge bytes; Smudge samples an immutable source snapshot behind the drag direction, blends by Flow and radial coverage, preserves destination alpha and skips hidden RGB in transparent pixels. The O shortcut cycles the tonal trio, R cycles Rotate View and Smudge, and settings survive local/project reload. Straight-segment Pen and Direct Selection now add editable path layers with local nodes, fill/stroke rendering, transformed node drags, history-safe cancellation and project round trips. Parametric polygon layers now support deterministic Triangle and Star variants with editable side count, fill/stroke controls, legacy defaulting and malformed metadata rejection; geometry and desktop round-trip coverage are in `vectorShapes.ts` and `advanced-shapes.spec.ts`. It also adds persisted layer folders: group/ungroup, rename, collapse/expand, visibility, opacity and locking; Quick Mask and named saved selections; nondestructive RGB/per-channel Curves; and raster layer-mask controls for invert, disable/enable and removal while retaining immutable source pixels. **Layer → Arrange** now provides Photoshop-style Bring to Front, Bring Forward,
Send Backward and Send to Back for selected layers. The immutable planner
preserves stack-order selection, active-layer identity and source metadata,
creates one undoable history step, and disables empty, locked or boundary
no-op moves. Selecting a folder member expands to the complete folder block,
moving it atomically while retaining member order and isolated blend/opacity
semantics; missing folder metadata fails closed. See
[`layer-arrange-contract.md`](./layer-arrange-contract.md).

**Layer → Merge Layers** now combines either the active layer with the immediately
lower visible, unlocked, ungrouped layer, a contiguous selected root-level
range, or a complete selected folder. Folder members are rendered through the
isolated group surface and the replacement retains the folder identity, so
folder opacity/blend is applied once. The selected range is rendered through the
normal transform, blend, opacity, adjustment, style and mask pipeline into one
frame-sized raster while unaffected and hidden layers remain intact. The
operation is undoable and source-safe; mixed folder/root, hidden, locked,
non-contiguous and insufficient selections remain guarded, and partial artboard membership is rejected before rendering. Planning and guard coverage live
in [`tests/layer-merge.test.mjs`](../tests/layer-merge.test.mjs), with the
desktop/mobile pixel, history and project round-trip gate defined in
[`docs/layer-merge-contract.md`](./layer-merge-contract.md).

## Extensive test contract

“Each implemented feature should come with extensive tests” is a release requirement. A feature means a tool, menu command, dialog behavior, persisted setting, import/export path or workspace mode—not only a large toolbar family. Tests should be added with the implementation and name the feature in their title.

| Test layer | Required coverage for every implemented feature | Evidence expected before enabling the menu/tool |
| --- | --- | --- |
| Pure behavior | Valid inputs, smallest useful canvas, transparent and opaque pixels, deterministic output, invalid settings and no-op/identity settings | Focused unit tests for geometry, selection algebra, color math, command validation or serialization |
| Document safety | Undo and redo, interaction with a selection/mask, hidden/locked layers, active-layer changes, concurrent gestures and cancellation | Browser or integration test proves source/editable layers and history remain correct |
| Persistence | Autosave/local reload, bookmark/project reopen, schema validation/migration and export/import round trip | Round-trip fixture compares editable properties, assets, masks and metadata rather than only a screenshot. Large local drafts use the versioned checksummed IndexedDB manifest/blob contract in [`draft-storage-contract.md`](./draft-storage-contract.md), with atomic pointer writes and corruption recovery tests |
| Interaction | Keyboard shortcut, toolbar/menu activation, pointer/touch or pen fallback, focus order, Escape/outside-click recovery, disabled-state labeling | Desktop and mobile browser tests with accessible names and shortcut behavior |
| Visual/data correctness | Representative pixel/alpha assertions, dimensions, color/units/quality metadata and expected error state | Golden fixtures are deterministic and tolerate no silent clipping, flattening or upload |
| Scale/reliability | Large/odd aspect images, memory/time budget, worker cancellation, malformed file, storage/network failure and retry | Targeted performance/failure test or documented reason the feature is local-only |
| Release/live | Typecheck, lint, production build, full browser suite and deployed-revision smoke check | CI run identifies commit; live check verifies the enabled action and persisted result on the deployed revision |

Feature-specific additions are mandatory where applicable: raster tools require before/after pixel and alpha-edge fixtures; selections require replace/add/subtract/intersect/invert/feather and disconnected-region fixtures; vector/text tools require path/metrics round trips and fallback fonts; menus require complete enabled/disabled inventory and command scope tests; dialogs require cancel/invalid/locale/resize cases; AI or remote actions require consent, quota, privacy, offline and cancellation tests. Shared test helpers are encouraged, but one passing helper test does not count as coverage for every effect or command.

## Delivery gates

1. Add the data model before exposing a tool that needs persistence (selection paths, masks, paths, adjustment commands and history references).
2. Every tool gets an accessible toolbar control, a keyboard shortcut where one is defined, mobile pointer behavior and a focused acceptance test.
3. Every raster operation is undoable, preserves the original asset until an explicit destructive action, and has at least one representative pixel assertion.
4. Every persisted property is validated, migrated and round-tripped through local and private cloud project files.
5. CI must run the desktop/mobile browser suite before production promotion; live deployment evidence must identify the tested commit.
6. AI, cloud asset sources and large-image processing remain opt-in and require an explicit privacy, quota and performance contract.
